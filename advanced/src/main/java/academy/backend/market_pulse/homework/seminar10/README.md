# Допзадание к семинару 10

author: Березецкая Варвара


Все классы решения находятся в этом пакете. Импортов классов реализации преподавателя
нет. Используются JDK 25 и уже подключённый к модулю Jackson для JSON.

## Запуск в IDEA

1. Для настоящих HTTP-запросов нужен сервер, отдающий JSON вида
   `[{"ticker":"SBER","price":123.45}]`.
   Можно запустить готовый сервер данных проекта:
   `docker compose -f docker/mockserver/docker-compose.yml up -d`.
2. Запустить **этот** `Main.java`.
3. По умолчанию адрес `http://localhost:1080/v1/instruments`, воркеров три.
   Для своего сервера задать Program arguments: `http://localhost:8080/quotes 4`.
4. В консоли вводить команды:

```text
watch SBER 3s 30s
watch GAZP 1s 1m
remove SBER
exit
```

Поддерживаются длительности `ms`, `s`, `m`, `h`, не более 365 дней.
Первый запрос запускается сразу. Последующие — через интервал после завершения
предыдущего. Ошибка HTTP выводится, после чего подписка продолжает работать.
При истечении срока запрос отменяется; результаты отменённых подписок не выводятся.
Если сервер не запущен, будут сообщения об ошибках соединения.

## Роли классов

- `Main`: основной поток читает команды; `exit` и EOF закрывают ресурсы.
- `Dispatcher`: отдельный поток хранит расписание, ставит задачи в пул и ждёт
  ближайшего срока или уведомления через `wait/notifyAll`.
- `Subscription`: сроки, состояния WAITING → QUEUED → RUNNING → WAITING,
  отмена и ссылка на выполняющий запрос поток. Поля защищены монитором диспетчера.
- `SimpleThreadPool`: фиксированные воркеры и FIFO `LinkedBlockingQueue<Runnable>`.
  `take()` блокирует свободный worker без активного опроса. Каждая задача достаётся одному воркеру.
- `QuoteClient`: выполняет HTTP, проверяет статус и извлекает цену по тикеру из JSON.

После запроса worker в `finally` освобождает подписку, обновляет `nextRun` и будит
диспетчер. Пока подписка QUEUED или RUNNING, ещё один запрос для неё не ставится.
Отмена и смена выполняющего потока согласованы одним монитором, чтобы не прервать
случайно следующую задачу этого worker.

## Завершение и ограничения

Сначала останавливается диспетчер, затем пул отбрасывает ожидающие задачи,
прерывает выполняемые и ждёт окончания потоков через `join`. Задачи должны
реагировать на interrupt; принудительной остановки Java-потоков нет.
Очередь не ограничена по размеру. FIFO задаёт порядок извлечения, а не завершения.
Обработчик вывода должен быть быстрым: для простоты он вызывается под монитором
диспетчера. Закрывать программу нужно из основного потока, не из задачи/обработчика.
