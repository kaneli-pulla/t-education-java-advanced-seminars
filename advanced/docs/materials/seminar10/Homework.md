# Дополнительное задание: диспетчер и worker-потоки

Решение использует существующий диспетчер `QuoteSubscriptionService` и новый
`SimpleThreadPool`. HTTP-клиент, команды подписок и состояние `Subscription`
сохранены из семинарского примера. Собственная часть решения — пул с блокирующей
FIFO-очередью, его подключение и тесты. Исходный `TreiberThreadPool` оставлен
для сравнения.

## Путь задачи

1. `SubscriptionsCommand` принимает `watch` или `remove` в основном потоке.
2. Поток `quote-dispatcher` проверяет сроки подписок и резервирует готовый запрос.
3. `submit()` помещает `Runnable` в `LinkedBlockingQueue`.
4. Один из фиксированных worker-потоков получает задачу через `take()` и выполняет её.
5. В `refresh()` блок `finally` обновляет `nextRun` через `finishRequest()` и будит
   диспетчер. Интервал отсчитывается после завершения запроса.

Состояния IDLE, QUEUED и RUNNING не позволяют поставить несколько запросов одной
подписки одновременно. Отмена подписки прерывает только закреплённый за ней запрос.

## Очередь и завершение

Очередь потокобезопасна и сама организует ожидание свободных воркеров. Дополнительные
`park/unpark` для пула не нужны. FIFO определяет порядок извлечения ожидающих задач,
но при нескольких воркерах порядок завершения не гарантируется.

`submit()` и `close()` согласованы монитором `lifecycle`. После закрытия новые задачи
отклоняются, ожидающие отбрасываются, воркеры прерываются и ожидаются через `join()`.
Выполняемые задачи должны реагировать на прерывание; принудительной остановки нет.
`close()` нельзя вызывать из воркера собственного пула.

Исключение RuntimeException задачи передаётся обработчику и не завершает worker.
Флаг прерывания после задачи очищается, чтобы отмена подписки не влияла на следующую.

## Проверка

Из корня проекта, с JDK 25 и Maven:

```shell
mvn -pl advanced -Dtest=SimpleThreadPoolTest,QuoteSubscriptionServiceTest,SubscriptionTest,SubscriptionHttpTest test
```

Тесты пула проверяют FIFO, конкурентную отправку без потерь и повторов, параллельное
выполнение, обработку ошибок, отмену и завершение потоков. Существующие тесты сервиса
проверяют интеграцию диспетчера с новым пулом.

Результат проверки на Windows / JDK 25.0.2: 27 из 28 тестов прошли. Проверка
`SubscriptionHttpTest.cancellationInterruptsHttpBeforeResponseBodyArrives(true)`
не дождалась следующего HTTP-результата за одну секунду. Тот же сбой воспроизведён
при временном возврате исходного `TreiberThreadPool`; это не специфичная для нового
пула регрессия. Причина HTTP-задержки пока не установлена, лимиты теста не менялись.
